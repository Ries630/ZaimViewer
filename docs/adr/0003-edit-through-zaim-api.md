# ADR-0003: 編集は必ず Zaim 更新 API を経由する

- ステータス: 承認済み
- 日付: 2026-08-06
- 関連: `be3b40a`、[#6](https://github.com/Ries630/ZaimViewer/issues/6)

## 背景

工程 ③ で明細の編集（カテゴリの付け替えなど）を作る。ミラー DB は手元にあるので、
技術的には直接 UPDATE できる。

しかし Zaim が唯一の正で、ミラーは同期のたびに全件入れ替わる
（[ADR-0002](0002-no-local-only-data.md)）。ミラーを書き換えても Zaim には届かず、
**次の同期で黙って消える**。しかも消えたことに気付けない。

一方、Zaim 更新 API は OAuth1.0a の署名を要求する。署名にはコンシューマシークレットと
アクセストークンシークレットが要り、これらはブラウザに置けない。

## 決定

編集はすべて Zaim 更新 API を経由する。ミラーへの直接書き込みはしない。
署名鍵をブラウザに出さないため、サーバ側に編集プロキシを立て、PWA はそこを叩く。

## 検討した代替

- **ミラーを直接更新し、あとで Zaim に流す** — 一時的にでも 2 つの正が生まれ、
  同期との競合を自前で解く羽目になる。ミラーを使い捨てにできる利点が消える
- **PWA から Zaim API を直接叩く** — 署名鍵がブラウザに露出する。
  加えて Zaim API は CORS を許していない

## 結果

- **バックエンドが必須になる。** これが [ADR-0001](0001-build-viewer-instead-of-generic-tools.md)
  で汎用ツールを落とした直接の理由になった
- 編集の反映が Zaim API のレスポンス待ちになる。一括編集では件数分の
  リクエストが直列に発生し、レート制限（同期では 0.3 秒間隔を入れている）と
  実行環境の上限に触れる。件数の上限を決める必要がある（[#6](https://github.com/Ries630/ZaimViewer/issues/6)）
- 編集直後、ミラーは古いまま。当該行だけ再取得するか同期を促すかを決める必要がある
