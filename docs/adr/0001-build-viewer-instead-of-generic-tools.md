# ADR-0001: 汎用ツールを使わず閲覧層を自作する

- ステータス: 承認済み
- 日付: 2026-08-06
- 関連: `be3b40a`（この判断が記録された最初のコミット）

## 背景

Zaim のフィルタ機能が弱く、自動連携で入る細かな履歴や振替に、重要な入出金が
埋もれる。これを解決するのに「閲覧層を自分で作る」以外の選択肢として、
既存の汎用ツールに DB を読ませる案があった。

前提として、この用途には**閲覧だけでなく編集も要る**。埋もれた明細を見つけたら
その場でカテゴリを直したい、というのが元の困りごとに含まれている。

## 決定

Directus / NocoDB / Metabase といった汎用ツールは使わず、閲覧層を自作する。

## 検討した代替

- **Directus / NocoDB** — DB を繋ぐだけで管理画面と REST API が生える。
  最初はこれが本命だった
- **Metabase** — 閲覧と集計に強い。ただし編集はできない

いずれも主価値は「API とダッシュボードの自動生成」にある。ところが編集を
Zaim に届けるには OAuth1.0a で署名するプロキシが必須で（[ADR-0003](0003-edit-through-zaim-api.md)）、
**バックエンドを書く前提が動かせない**。バックエンドを書くなら、自動生成された
API はもう仕事をしていない。汎用ツールを足すぶんだけ構成が増える。

## 結果

- 明細一覧・フィルタ UI・ページングをすべて自分で書くことになる
- 集計とグラフも自前になる。Metabase なら無料で付いてきた部分を失う
  （当初は Grafana で補う想定だった。[ADR-0010](0010-d1-as-mirror.md) で D1 に
  移ったためこの経路は切れており、集計が要るなら Worker 側にエンドポイントを足す）
- 代わりに、UI をこの用途に振り切れる。「振替を除外」「1,000 円未満を隠す」のような、
  汎用ツールでは毎回手で組み直すことになる操作を既定にできる

## 再評価のサイン

- 閲覧側の作り込みが目的に対して重くなり、フィルタよりも UI の保守に時間を使い始めたとき
