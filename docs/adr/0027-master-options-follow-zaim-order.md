# ADR-0027: フィルタの選択肢は Zaim の並びに従わせ、削除済みマスタは参照されているものだけ残す

- ステータス: 承認済み
- 日付: 2026-08-14
- 関連: [#15](https://github.com/Ries630/ZaimViewer/issues/15)、[ADR-0002](0002-no-local-only-data.md)（Zaim が唯一の正）、[ADR-0026](0026-filter-defaults-and-persistence.md)（フィルタ UI）

## 背景

フィルタパネルの選択肢が「普段の並び順でない」という指摘を受けて、本番のミラーを
調べた。3 つの原因があった。

### ① 削除済みのマスタを選択肢に出していた

`active` は同期しているのに `/api/masters` が見ていなかった。

| | 全件 | `active = -1` | 参照する明細 |
|---|---|---|---|
| カテゴリ | 46 | 18 | **0** |
| 口座 | 36 | 5 | 18（全 4,370 件の 0.4%） |
| ジャンル | 129 | 0 | - |

**削除済みのマスタは `sort` が 0 に潰れる。** そのため `sort` で並べると必ず先頭に来る。
実際、口座を開いたときの先頭 4 件（Olive / 三井住友カード Amazonマスター /
Amazon ギフトカード / モバイルSuica）はすべて削除済みだった。カテゴリの先頭に出る
「給料」も削除済みで、実際に使われているのは同じ意味の「Salary」の方だった。

### ② カテゴリを `mode` の辞書順で並べていた

`ORDER BY mode, sort, id` としていたため `income` < `payment` となり、収入カテゴリが
支出より先に出ていた。Zaim の画面は支出が先。

### ③ ジャンルの見出しが `category_id` の数値順だった

`ORDER BY category_id, sort, id` はカテゴリ自身の `sort` を無視するので、
ジャンルの見出しの順序とカテゴリ一覧の順序が揃わなかった。

`sort` の値そのものは Zaim の並び順を正しく持っている（有効な支出カテゴリは
3, 7, 8, 11, 12, 13, 14… と飛び番で並ぶ。削除された分が抜けた跡）。
**並び替えの材料は同期済みで、使い方を誤っていただけだった。**

## 決定

`/api/masters` の組み立てを `worker/src/queries.ts` の `fetchMasters` に移し、次の
規則で返す。

1. **`active = 1`、または明細から参照されているマスタだけ返す**
2. **並びは「有効なものが先 → 支出・収入の順 → Zaim の `sort` → id」**
3. **ジャンルはカテゴリの並びに従わせる**（カテゴリを引けないジャンルは末尾）
4. **`active` をレスポンスに含め、UI は削除済みに「削除済み」と印を付ける**

結果、カテゴリ 46 → 28 件、口座 36 → 33 件、ジャンルは 129 件のまま。

## 検討した代替

- **`active = 1` だけ返す（参照の有無を見ない）** — 実装が最も短く、クエリに
  サブクエリが要らない。落としたのは、削除済み口座を使っている明細 18 件を
  口座で絞る手段が無くなるため。ミラーは Zaim の写しで、過去の明細は消えない
  （ADR-0002）のに、それを指す選択肢だけが消えるのは筋が悪い
- **全部返して並び順だけ直す（削除済みを末尾へ回す）** — 過去の明細をどのマスタでも
  絞れる。落としたのは、選択肢が 46 / 36 件のまま残るため。実データでは
  カテゴリの 39%（18/46）が削除済みで、しかもその 18 件はどの明細からも参照されて
  いない。絞る役に立たない選択肢が 4 割を占める
- **削除済みを別の折り畳みに分ける** — 一覧を汚さずに到達できる。落としたのは、
  残るのが口座 2 件だけで、折り畳みを 1 段増やす価値が無いため。
  この比率が変われば再検討する
- **UI 側（`src/lib/masters.ts`）で絞り込む** — API を変えずに済む。落としたのは、
  並び順の材料（カテゴリの `sort`、明細からの参照）が SQL の側にあり、
  クライアントでやると全件を持ってきてから捨てることになるため

## 結果

- **`/api/masters` のクエリにサブクエリが 3 本増えた。** マスタは起動時の 1 回しか
  引かない（`staleTime: Infinity`）ので実用上の負担は無いが、D1 の
  invocation あたりクエリ数（無料枠 50）を数えるときの前提が変わる
- **削除済みでも「参照されている」だけで選択肢に出る。** 利用者から見れば Zaim に
  無いものが並ぶので、印を付けても一瞬迷う余地は残る
- **Zaim 側で並び順を変えても、同期するまで反映されない。** 同期は 1 日 1 回
  （launchd で毎日 06:00）なので、並べ替えた当日は古い順序のまま
- **ジャンルの見出し順がカテゴリの `sort` に依存するようになった。** Zaim で
  カテゴリを並べ替えると、ジャンルの見出し順も一緒に動く

## 再評価のサイン

- **削除済みかつ参照されているマスタが増えたとき。** 今は口座 2 件だけなので
  一覧に混ぜているが、増えるなら別の折り畳みに分ける
- **`sort` が Zaim の並びを反映しなくなったとき。** Zaim API の仕様変更で、
  この ADR の前提（材料は同期済み）が崩れる
- **カテゴリやジャンルの数が大きく増えたとき。** 28 / 129 件を縦に並べる形
  （ADR-0026 で決めた容れ物の中の選択部品）は、そこで初めて比較の対象になる。
  今回は並び順を直すだけで足りると判断して部品には手を付けていない
