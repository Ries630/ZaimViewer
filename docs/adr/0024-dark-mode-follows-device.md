# ADR-0024: ダークモードは端末の設定に従い、色の上書きは light 側だけに閉じる

- ステータス: 承認済み
- 日付: 2026-08-13
- 関連: [#21](https://github.com/Ries630/ZaimViewer/issues/21)、[#18](https://github.com/Ries630/ZaimViewer/pull/18)、[ADR-0022](0022-daisyui-for-form-components.md)・[ADR-0023](0023-darken-success-for-income-amount.md)（どちらも再評価のサインがここで満たされた）

## 背景

[#18](https://github.com/Ries630/ZaimViewer/pull/18) で表示をライトに固定したとき、
ダークモードの入れ方を「DaisyUI の採否を決めてから」と保留していた。当時 UI は素の
Tailwind だけで、`dark:` を全コンポーネントに撒いてもテーマ機構に載せ替えるときに
捨てることになるため。[#20](https://github.com/Ries630/ZaimViewer/pull/20) で
パレット直書きが 0 になり、ADR-0022 の「ダークモードを入れる判断をするとき。semantic
トークンで書き切れているかがそこで試される」と、ADR-0023 の「ダークモードを入れるとき」
に同時に到達した。

`dark --prefersdark` を足しただけの状態で、両テーマのコントラスト比を測った。手順は
#20 と同じ（Chrome を iPhone 幅 430×932 にし、canvas 経由で sRGB に落として WCAG 2.1 の
相対輝度で計算）。

**#20 の測り方には誤りがあった。** 半透明の色（`text-base-content/60` など）を常に白の
上で合成していた。ライトでは地が白なので結果は正しかったが、ダークでは値が狂う
（補足が `base-content` 本体より高く出た）。実際に敷かれている地色の上で合成するよう
直したうえで測り直している。

| 箇所 | light | dark |
|---|---|---|
| 支出の金額 `base-content` | 17.72 | 14.75 |
| 収入の金額 `success` | 5.05 | 8.08 |
| 振替の金額・文脈 `/60` | 4.66 | 6.21 |
| 補足 `/50` | 3.40 | 4.77 |
| 総額 `/70` | 6.57 | 7.97 |
| エラー `error` | **2.86** | 5.53 |
| 「予定」バッジ 文字/地 | 6.34 | 6.34 |
| 「予定」バッジ 地/ページ | 2.22 | 7.13 |
| 「同期が古い」文字/地 | 5.24 | 5.24 |
| popover 地/ページ | 19.90 | **1.26** |

分かったのは 2 つ。

- **popover が dark で背景に溶ける。** `bg-neutral` を使っていたが、dark テーマの
  neutral は `base-100` とほぼ同じ暗さで 1.26:1。light では「暗い吹き出し」として
  成立していた反転が、dark では成立しない
- **light の error が 2.86:1 で読めない。** これはダークモードとは無関係で、#20 で
  `text-red-600`（4.77:1）から `text-error` に置き換えたときに測り漏らしていた。
  組み込み light の error は明度 71% で、success（76%）と同じく地色向けの値

## 決定

1. **端末の設定に従う。** `themes: light --default, dark --prefersdark;`。テーマの
   切り替え UI は持たない
2. **色の上書きは light 側だけに閉じる。** dark は組み込みの既定のまま置く。暗い地
   では明るい success / error の方が読める（8.08:1 と 5.53:1）
3. **light の error も ADR-0023 の success と同じ要領で暗くする。**
   `oklch(55% 0.19 13.428)` で 5.38:1
4. **popover は `bg-base-content` / `text-base-100` にする。** この 2 つは必ず対比する
   よう定義されているので、テーマが増えても反転が保たれる（light 17.72、dark 14.75）

## 検討した代替

- **dark の neutral を明るく上書きして、popover の反転を保つ** — JSX を触らずに済む。
  落としたのは、neutral が popover 専用の色ではないため。将来 `btn-neutral` などを
  使うとそこも一緒に動く。欲しいのは「地と文字が必ず対比すること」で、それを直接
  表しているのは `base-content` / `base-100` の組の方
- **popover に `bg-base-300` を使い、面の段差で見せる** — dark では base-300 が
  base-100 より明るいので浮く。しかし light では 95% でほぼ白（1.16:1）になり、白地の
  上で境界が消える。両テーマで成立しないので落とした
- **テーマ切り替え UI を持つ** — （未検討）。閲覧は iPhone のホーム画面からで、OS の
  設定と食い違わせたい場面がまだ無い

## 結果

- **テーマを増やすなら、その都度この 10 箇所を測り直すことになる。** 上書きを light に
  閉じた結果、テーマごとに「地色向けの色を文字に使っていないか」を見る作業が要る。
  lint でも型でも防げない
- **popover は neutral の見た目から外れた。** 将来 `btn-neutral` のような neutral の
  部品を足しても、popover とは揃わない
- **補足（`text-base-content/50`）は light で 3.40:1 のまま**で、WCAG AA の 4.5 に
  届いていない。3 段目の補足表示に限る割り切りとして残す（置き換え前の `gray-400` は
  2.60:1 だったので改善はしている）
- CSS は dark テーマのぶんが raw で +3.9 kB（49.88 → 53.78 kB、gzip 9.35 → 9.67 kB）。
  ただし同じ PR で Tailwind の走査対象から `docs/` と `CLAUDE.md` を外したため、
  最終的には raw 36.35 kB / gzip 7.52 kB と main より小さくなった。ADR や CLAUDE.md が
  地の文で書いたクラス名（`text-gray-500` など、実装では 1 箇所も使っていない）が
  ビルドに入っていたことによる

## 再評価のサイン

- **テーマを 3 つ目以降に増やすとき。** 上書きが light に閉じているという前提が崩れる
- **補足表示を「読ませたい情報」に格上げするとき。** 3.40:1 では足りない
- **DaisyUI が dark テーマの neutral と base-100 の関係を変えたとき。** popover を
  `base-content` にした理由が消える
- 端末の設定と別のテーマで見たくなったとき（切り替え UI の要否をそこで検討する）
