# ADR-0037: 一括編集は対象を固定し、画面から一件ずつ実行する

- ステータス: 承認済み
- 日付: 2026-09-05
- 関連: [#6](https://github.com/Ries630/ZaimViewer/issues/6)、[#76](https://github.com/Ries630/ZaimViewer/issues/76)、[ADR-0036](0036-refresh-edited-mirror-with-shared-gate.md)

## 背景

検索条件に一致する明細は、編集そのものによって検索結果から外れる。取得済みの画面の行や、
更新のたびに再検索したページを順に処理すると、未取得行の取りこぼしやページのずれが起こる。
また、外部更新後に通信が切れた場合、クライアントには成功が届かなくても Zaim に保存されて
いる可能性がある。Workers の HTTP 処理は接続切断後の継続を保証しない。

## 決定

Worker が対象と確認時の値・変更内容を固定した編集計画を D1 に保存し、単体編集も同じ経路を
使う。PWA は確認済み計画の一件だけを各要求で実行する。結果を計画に記録し、同じ計画の
成功済み明細を再実行しない。対象数、期限、リクエスト間隔の正は `worker/src/edit-contract.ts`
とし、値は実測後に再評価する。

画面を閉じる、バックグラウンドへ移る、通信や認証が途切れる場合は新規送信を止める。
再表示では保存済みの計画を取り直し、結果不明の明細は更新を再送する前に照合する。
ブラウザには計画 ID だけをセッション単位で保存する。新規実行の期限が切れても、未確認の
結果の照合を期限だけで禁止しない。

## 検討した代替

- 全件を一つの Worker 要求で処理する: 件数に比例して CPU と外部要求数が増え、途中切断時の結果が扱いにくい。
- バックグラウンドジョブ: 画面を閉じても進められるが、初期版に別の実行基盤と再試行制御が必要になる。
- クライアントだけで対象と結果を保持する: 再読み込みや応答喪失の後にサーバで結果を確認できない。

## 受け入れた代償

一括編集を進める間は画面を開いておく必要がある。処理は全件一括のトランザクションではなく、
停止前に成功した分は保存されたままになる。処理管理用データは全件同期で消さず、復旧のため
未確認の結果を保持する。計画の保持・削除は [編集の運用手順](../../ops/editing.md) を参照する。

## 再評価の条件

初期上限では普段の編集が繰り返し分断される場合、またはバックグラウンド継続が必要になった場合。
