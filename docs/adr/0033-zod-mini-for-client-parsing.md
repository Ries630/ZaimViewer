# ADR-0033: クライアント側の入力検証に `zod/mini` を使う

- ステータス: 廃止（ADR-0034 により置換）
- 日付: 2026-08-19
- 関連: [#44](https://github.com/Ries630/ZaimViewer/issues/44)、[ADR-0026](0026-filter-defaults-and-persistence.md)、[ADR-0032](0032-anti-slop-lint-rules.md)

## 背景

[ADR-0032](0032-anti-slop-lint-rules.md) の第 3 段で `no-unknown-parameters` と
`no-runtime-typeof` を有効にする。この 2 つが指していたのは `src/lib/filter-storage.ts` の
17 件で、localStorage から読んだ値を `unknown` で受け、`typeof` の手書きガードで
検証している箇所だった。

**手書きのまま両立させることはできない。** `no-runtime-typeof` は
`allowInTypeGuards: true` で型述語関数（`value is Foo`）の中を許すが、その型述語関数の
引数は `unknown` なので `no-unknown-parameters` に掛かる。境界の検証をパーサに
任せる以外に、この 2 つを同時に満たす書き方が無い。

一方 `filter-storage.ts` には「zod を使わないのは、この 1 か所のためにクライアントの
バンドルへ載せる価値が無いため」と書いてあった。載せる価値があるかを測り直すのが
この判断になる。

実装を 2 通り書き、`bun run build` の出力で比べた。挙動はどちらも既存の
テスト（205 件）が全通過している。

| 実装 | クライアント JS | gzip | precache 合計 |
|---|---|---|---|
| 手書きの `typeof` ガード | 313.53 kB | 100.19 kB | 376.24 KiB |
| `zod`（本体） | 378.06 kB | 117.51 kB | 439.25 KiB |
| `zod/mini` | 331.03 kB | 105.48 kB | 393.33 KiB |

**本体は gzip で +17.32 kB、mini は +5.29 kB。** 差は 12.03 kB で、mini は本体の
3 割ほどしか増えない。

## 決定

クライアント側の検証は `zod/mini`（`import * as z from "zod/mini"`）で書く。
Worker 側は従来どおり `zod` 本体と `@hono/zod-validator` のままにする。

## 検討した代替

**`zod` 本体をクライアントにも載せる。** Worker と同じ記法で書けて、スキーマを
共有する道も開ける。落としたのは gzip 12.03 kB を払う理由が今は無いため。
`filter-storage.ts` の 1 ファイルにしか使わないので、記法が揃う利点も現時点では
実質的に効かない。

**手書きのガードを残し、2 ルールを不採用にする。** ルールが指していた「zod を
依存に持ちながら localStorage の復元だけ手書き」は実在の穴で、指摘の質は高かった。
`z.catch` を項目ごとに置く形は、手書きの `asBoolean` / `asString` … を 1 つずつ
足していく形より、項目を増やすときの取りこぼしが起きにくい。

**valibot などの軽量ライブラリを入れる。** 依存が 1 つ増える。zod は既に依存に
あり、mini がその中に入っているので、増やす理由が無い。

## 結果

**同じリポジトリに zod の書き方が 2 種類並ぶ。** Worker 側は
`z.string().min(1)` のメソッドチェーン、クライアント側は
`z.catch(z.string().check(z.minLength(1)), …)` の関数呼び出しになる。
書き分けを覚える必要があり、どちらの流儀か迷う場面が出る。

**クライアントのバンドルが gzip 5.29 kB 増える。** Service Worker の precache も
同じだけ増える（376.24 → 393.33 KiB）。デプロイのたびに端末が取り直す量が増える。

**倒れた理由は捨てている。** `z.catch` は失敗を握り潰して既定値に倒すので、
「どの項目がなぜ読めなかったか」は残らない。手書きのときと同じ挙動だが、
zod にしても診断が増えるわけではない。

**配列の中身の検証が 1 段深くなった。** 異物を 1 件ずつ落とす挙動
（ADR-0026 の「項目ごとに倒す」より細かい既存の挙動）を保つため、`sieve` の中で
要素ごとに `safeParse` を呼んでいる。素直に `z.array(z.int())` と書くより回りくどい。

## 再評価のサイン

- 工程 ③ の編集フォームで検証が要るようになり、Worker とスキーマを共有したく
  なった → 共有できる形（本体に揃える）と mini のままの費用を測り直す
- クライアントで検証する箇所が増え、mini の記法の読みにくさが実際に効いてきた
  → gzip 12 kB を払って本体に揃えることを検討する
- `zod/mini` の API が本体と大きく乖離した、または配布が止まった → 選び直す

## 廃止の経緯

翌日（2026-08-20）に valibot への一本化を決め、[ADR-0034](0034-valibot-for-validation.md) が
この判断を置き換えた。

この ADR が測ったのは**クライアント側のバンドルだけ**で、zod 本体を Worker から
外したときの取り分（gzip 17〜22 kB）を測っていなかった。「1 ファイルのために本体を
載せる理由が無い」までは正しかったが、比べる先が足りていない。
