# ADR-0038: 編集送信はアプリで管理し、シートの寿命から分離する

- ステータス: 承認済み
- 日付: 2026-09-07
- 関連: [#75](https://github.com/Ries630/ZaimViewer/issues/75)、[#76](https://github.com/Ries630/ZaimViewer/issues/76)、[#80](https://github.com/Ries630/ZaimViewer/pull/80)、[ADR-0037](0037-foreground-edit-plans.md)

## 背景

単体編集、一括編集、一覧からの再開が、それぞれ送信と照合を管理していた。
シートを閉じる操作が実行停止に結び付き、未完了の一括編集では入力・確認状態も残っていた。
利用者が一覧へ戻っても処理を追えるようにするには、編集処理と表示の寿命を分離する必要がある。

## 決定

アプリに一つの EditPlanRunner を置き、送信、停止、手動再開、照合、計画の復元を管理する。
単体編集、一括編集、一覧の状態表示は同じ実行状態を参照し、Runner へ操作を依頼する。
入力・確認状態はシートが所有し、閉じたら破棄する。保存操作以降は、単体編集の計画作成も
含めて Runner が所有する。シートを閉じても、アプリが前景かつオンラインなら送信を続ける。

背景移行、ページ離脱、通信断、認証切れ、明示的な停止では次の送信を開始しない。
送信済み要求は取り消されたと見なさず、その結果を収める。復帰や再読み込みでは自動再開せず、
保存済み計画を取得して状態を確認する。結果不明は更新を再送する前に照合する。

Worker が対象と変更内容を固定し、要求ごとに一件を実行する方式を維持する。
Zaim が唯一の正であり、照合とミラー反映・同期との共有排他は
[ADR-0036](0036-refresh-edited-mirror-with-shared-gate.md) に従う。
対象数、期限、送信間隔の正は `worker/src/edit-contract.ts` とする。

同一タブで追跡する未完了計画は一つとし、別の保存で上書きしない。
ブラウザの永続領域には計画 ID だけをタブ単位で保存する。
計画の追跡終了と D1 からの削除は別操作とし、条件は
[編集の運用手順](../../ops/editing.md) を参照する。

## 検討した代替

- シートと再開表示から同じ関数を呼ぶだけにする: 実行の寿命が呼び出し元に残り、閉じる操作との結合を解消しない。
- 確認画面を閉じられなくする: 入力の破棄と送信処理の保持を分離できず、送信中に一覧へ戻る用途も解決しない。
- サーバーのバックグラウンドジョブへ移す: 今回必要なのはシートを閉じた後の前景実行であり、別の実行基盤と再試行制御は導入しない。

## 受け入れた代償

シートを閉じても送信は止まらないため、一覧にも停止操作と結果表示が必要になる。
アプリを背景へ移すと送信は止まり、前景へ戻しただけでは続かない。
複数タブを一つの Runner では管理せず、Worker の共有排他と各計画の実行状態に従う。
処理は一括トランザクションではなく、停止前に成功した分は保存されたままとなる。

## 再評価の条件

アプリを背景にした状態での継続や、複数計画・複数タブをまとめた実行管理が必要になった場合。
