# ADR-0029: 明細の詳細をボトムシートで見せ、そこを工程 ③ の編集の入口にする

- ステータス: 承認済み
- 日付: 2026-08-16
- 関連: [#19](https://github.com/Ries630/ZaimViewer/issues/19)、[#6](https://github.com/Ries630/ZaimViewer/issues/6)、[ADR-0021](0021-no-list-virtualization.md)、[ADR-0022](0022-daisyui-for-form-components.md)

## 背景

一覧の主表示（店舗名 / 品名）は 1 行 `truncate` で、長いものは末尾が切れる。
**一覧としてはこれで許容できることは #14 の実機確認で分かっている**が、切れた先を
読む手段が無かった。本番の実データでは `name` が最長 60 文字、`place` が最長 30 文字、
`comment` が最長 60 文字（全 4,370 件で計測）。

同時に、工程 ③（[#6](https://github.com/Ries630/ZaimViewer/issues/6)）で単体編集の
UI を作ることが決まっている。編集は必ず Zaim 更新 API を経由する
（[ADR-0003](0003-edit-through-zaim-api.md)）が、**画面のどこから編集に入るかは
決まっていなかった。**

一覧の行に対して使える操作は、タップ・長押し・スワイプの 3 つしかない。
このうちタップだけが iPhone で発見しやすい。#19 と #6 はどちらもその 1 つを
欲しがっており、**先に決めた方が後から決める方を追い出す**関係にある。

## 決定

一覧の行をボタンにし、タップで明細の詳細をボトムシートに出す。シートは
店舗・品名・メモを畳まずに折り返して全文を出す。

**このシートを工程 ③ の単体編集の入口にする。** シートに出す項目は Zaim の更新 API が
受け付けるものに合わせ、編集フォームになったときに読める項目と直せる項目がずれない
ようにする。

出し方は値の性質で分ける。自由入力の項目（店舗・品名・メモ・カテゴリ・ジャンル・
出金元・入金先）はラベルと値の対で並べ、値が定まっている項目は見出しに置く
（日付・金額と、支出 / 収入 / 振替の 3 つしかない種別）。種別をバッジにするのは、
ラベルと値を並べるより速く読めるうえ、金額を修飾するものだから。

メモの中のタグ（`#MUFG取込` など）は平文と見分けが付く形にする。実データでは
メモのある 3,959 件のうち 3,877 件（98%）がタグを含み、`RTK LINE PAY 31-03-31
#MUFG取込 #振替変換待ち` のように平文と混ざるため、同じ見た目だと埋もれる。

実装は絞り込みシート（[#15](https://github.com/Ries630/ZaimViewer/issues/15)）と同じ
`dialog.modal` + `modal-bottom` に揃える。

## 検討した代替

- **タップで該当行だけ折り返す** — 実装は数行で済む。落としたのは、これが行タップを
  先に使ってしまい、#6 の編集の入口を長押しかスワイプへ追い出すため。行内に編集
  フォームは置けないので、#6 の時点でこの実装は捨てることになる
- **長押し・スワイプ** — タップを #6 のために空けておける。落としたのは、iPhone で
  発見しづらい操作をこのアプリに 2 つ持つことになるため（1 つ目は絞り込みシート）
- **daisyUI の `drawer`** — 横から出す。落としたのは、`drawer` が checkbox と
  `z-index` で組まれていて native `dialog` の top-layer・ESC・focus trap をすべて
  自前で書き直すことになるため。加えて「ページの中身をすべて `drawer-content` の
  中に置く」という構造要件があり、`App.tsx` のヘッダ・main・既存シートを包み直す
- **全画面モーダル** — キーボードが出たときに余裕がある。落としたのは、背後の一覧が
  見えなくなり「開く → 閉じる → 次の行」の往復で位置を見失うため。キーボードの
  余裕という利点も、絞り込みシートが金額とキーワードの入力欄を持ったまま
  `modal-bottom` で実機を通っている以上、必要になっていない

## 結果

- **一覧の行タップは詳細シート専用になった。** 一覧から直接なにかを操作する機能
  （その場でカテゴリを変える、選択して一括操作するなど）は、別の操作か別の
  モードを用意しないと載せられない。[#6](https://github.com/Ries630/ZaimViewer/issues/6)
  の一括編集は一覧の行からではなく、フィルタ結果に対する操作として作ることになる
- 行が `<button>` になったので、中の 3 段を `<p>` では組めなくなった
  （button の中に置けるのは phrasing content だけ）。`<span class="block">` に
  変えてある
- **シートは開いても選択した明細を保持し続ける。** daisyUI の modal は閉じるときに
  遷移が入り、そこで中身を空にすると一瞬だけ空のシートが見える。閉じた時点では
  状態を捨てない
- 詳細に出せるのは `/api/transactions` が返す項目だけ。`receipt_id` や `created` は
  ミラーにはあるが API が返しておらず、出すなら API 側を変えることになる

## 再評価のサイン

- [#6](https://github.com/Ries630/ZaimViewer/issues/6) で編集フォームを載せたとき、
  シートの高さ（`max-h-[85vh]`）にキーボードと入力欄が収まらなかった場合。
  そのときは全画面モーダルを再検討する
- 一覧から複数件を選ぶ操作が必要になったとき。行タップが埋まっているので、
  選択モードの出し方から決め直すことになる
