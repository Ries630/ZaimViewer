# ADR-0017: 設計判断を ADR として `docs/adr/` に残す

- ステータス: 承認済み
- 日付: 2026-08-10

## 背景

これまで設計判断は CLAUDE.md の「設計上の決定と理由」に書いていた。
Claude Code のセッション開始時に自動で読み込まれるので、結論が毎回文脈に入る
という利点がある。実際、この置き場所自体が意図的な選択だった（`be3b40a`:
「旧スコープに置いた設計判断のメモが読み込まれなくなるため、リポジトリと
一緒に移動する CLAUDE.md に集約する」）。

問題は、CLAUDE.md が**現在の姿を書く文書**であることにある。実態が変われば
上書きされる。その結果、判断の履歴が消える。

実害が既に出ていた。`0cc81d0` で Python + FastAPI + ローカル SQLite から
乗り換えた際、**当初なぜ Python と SQLite を選んだのかがリポジトリから消えた**。
残ったのは移行後に書かれた 3 行の要約だけで、「何を見落として乗り換えることに
なったのか」は追えなくなっていた（今回 `be3b40a` 時点の CLAUDE.md から
[ADR-0004](0004-sqlite-as-mirror.md) と [ADR-0005](0005-tailscale-for-access.md) を復元した）。

さらに、CLAUDE.md は毎セッション全文が文脈に入る。理由と却下案を全部そこに
書き続けると、読まれない情報にトークンを払い続けることになる。

## 決定

設計判断は `docs/adr/` に 1 決定 1 ファイルで残す。形式は MADR を削ったもの
（背景 / 決定 / 検討した代替 / 結果 / 再評価のサイン）。

CLAUDE.md には**結論と 1 行の理由、そして ADR へのリンク**だけを置く。

- **結論**は毎セッション文脈に要る。そこに無いと同じ提案が蒸し返される
- **理由・却下案・その時点の測定値**は必要なときに読めればよく、
  しかも後から上書きされては困る

一度書いた ADR の本文は編集しない。判断が変わったら新しい ADR を書き、
古い方はステータス行だけ `廃止（ADR-XXXX により置換）` に変える。

## 検討した代替

- **CLAUDE.md 内に節を分けて残す** — 履歴が残らないという元の問題が解決しない。
  ファイルも際限なく伸びる
- **GitHub の Issue / Discussion に残す** — リポジトリを clone しても付いてこず、
  grep もできない。オフラインで読めない。ただし**議論の場としては Issue が適切**で、
  実際 [#3](https://github.com/Ries630/ZaimViewer/issues/3) や
  [#5](https://github.com/Ries630/ZaimViewer/issues/5) には判断の材料が揃っている。
  Issue で迷い、決まったら ADR に落とす、という役割分担にする
- **コミットメッセージに残す** — 既にかなり書けている（`0cc81d0` や `70a945f` の
  本文は実質 ADR）。ただし `git log` を掘らないと読めず、決定が複数コミットに
  跨がる場合や、決定が変わった場合の追跡ができない

## 結果

- 判断のたびに 1 ファイル書く手間が増える。この手間に見合わない小さな判断を
  ADR にしないための基準を [README](README.md) に置いた。とくに
  「テストや型で守られているものは書かない」が効く
- CLAUDE.md が短くなり、毎セッションの文脈消費が減る
- ADR は自動では読み込まれない。**判断の理由に触れるには、その場で
  `docs/adr/` を読む必要がある。** CLAUDE.md 側のリンクがその入口になる
- 遡って 16 件を書いた。復元にはコストがかかったが、履歴が新しいうちが最も安い
