# ADR-0015: 同期は Worker の外（手元の Mac mini）で実行する

- ステータス: 承認済み
- 日付: 2026-08-07
- 関連: `bafc466`、[#3](https://github.com/Ries630/ZaimViewer/issues/3)

## 背景

[ADR-0009](0009-migrate-to-workers.md) の動機のひとつは「定期実行が Cron Trigger で
済み launchd を書かずに済む」ことだった。つまり同期も Worker 内で回す想定だった。

ところが実測と調査で、2 つの上限に当たることが分かった。

| 制限 | 値 | 同期の実測 |
|---|---|---|
| Workers の CPU 時間（無料、Cron Trigger 含む） | 10ms | 約 20ms |
| D1 の invocation あたりクエリ数 | 無料 50 / 有料 1,000 | 約 4,600 文 |

1 行目だけなら有料プランで解決する。効いたのは 2 行目で、
**クエリ数の制限は有料プランでも足りない**。約 4,600 文は 1,000 の 4 倍以上あり、
課金しても 1 回の invocation には収まらない。

一方、読み取り API は 1 リクエストあたり 2〜3 クエリで、無料の 50 に対して
1 桁以上の余裕がある。

## 決定

読み取り API と PWA 配信だけを Workers に置き、同期は手元の Mac mini から
実行して D1 の HTTP API 越しに書き込む。

## 検討した代替

- **有料プランに上げて Worker 内で同期する** — クエリ数の制限が解決しない
- **同期を分割して複数 invocation に跨がせる** — Durable Objects か Queues で
  状態を持つことになり、構成が増える。得られるのは「Mac mini を使わない」ことだけで、
  スリープ中でも**閲覧は**できるという主目的は既に満たされている
- **差分同期にしてクエリ数を減らす** — Zaim 側の削除を追えない
  （[ADR-0007](0007-atomic-swap-sync.md) と同じ理由）

## 結果

- **月額 0 円で運用できる。** 読み取りは無料枠に収まる
- **Mac mini がスリープ中でも iPhone から閲覧できる。** ミラーが古くなるだけで、
  見られなくなることはない。[ADR-0009](0009-migrate-to-workers.md) の主目的は達成される
- Cron Trigger を使わないので、結局 launchd（か相当の仕組み）を書くことになる。
  移行動機の 2 番目は失われた
- **アトミック差し替えはこの構成でも維持できる。** `*_new` への一括投入は
  多数のリクエストに分かれてよく、原子性が要るのは差し替えの 13 文だけで
  1 バッチに収まる（[ADR-0012](0012-table-swap-sync.md)）
- Worker 内に残っている `POST /api/sync` と `scheduled` ハンドラは本番では動かない。
  ローカル開発専用として残すか削除するかは [#3](https://github.com/Ries630/ZaimViewer/issues/3) で決める

## 再評価のサイン

- 手元での定期実行が運用として重くなったとき。その場合は
  Workers 内での分割実行か、[ADR-0010](0010-d1-as-mirror.md) の再評価
  （クエリ数制限の無い Turso）を検討する
