# ADR-0007: 同期は全件構築してからアトミックに差し替える

- ステータス: 廃止（[ADR-0012](0012-table-swap-sync.md) により置換）
- 日付: 2026-08-06
- 関連: `e8bcd61`

## 背景

同期は Zaim から全件（明細 4,362 件 + マスタ 211 件）を取得して入れ直す。
差分更新ではないのは、ミラーが使い捨てで、Zaim 側の削除を追う手段が
乏しいため（[ADR-0002](0002-no-local-only-data.md)）。

ここで 2 つの危険がある。

1. **途中の状態を読まれる。** 同期中に FastAPI や Grafana が読むと、
   件数が中途半端な DB を見ることになる
2. **失敗で壊れる。** Zaim API が異常を返したとき、素直に書くと空の DB が残る。
   認証が切れているだけでも全明細が消えたように見える

## 決定

一時ファイルに全件を構築し、`integrity_check` と 0 件チェックを通してから
`os.replace` で差し替える。認証確認と 0 件チェックは差し替えより**前**に置く。

## 検討した代替

- **既存 DB を DELETE してから INSERT** — トランザクションで囲えば原子性は
  保てるが、同期の全所要時間（約 1 分、44 リクエスト）にわたって書き込みロックを
  握り続ける。読み手が待たされる
- **差分更新** — Zaim 側で削除された明細を検出できない。ミラーに残り続ける

## 結果

- 読み手は常に完全な DB だけを見る。ロック競合も起きない
- 同期中はディスク上に DB が 2 つ存在する。数 MB なので問題にならない
- 認証失敗や API 異常のときは、既存 DB が無傷で残る

## 廃止の経緯

[ADR-0010](0010-d1-as-mirror.md) で D1 に移り、**ファイル差し替えに相当する操作が
無くなった**。「全件構築 → 検証 → アトミックに差し替え」という意図はそのまま
引き継ぎ、手段をテーブル単位に置き換えたのが [ADR-0012](0012-table-swap-sync.md)。
