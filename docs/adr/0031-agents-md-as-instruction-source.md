# ADR-0031: 指示ファイルを `AGENTS.md` に移し、`CLAUDE.md` はインポートだけにする

- ステータス: 承認済み
- 日付: 2026-08-19
- 関連: [#39](https://github.com/Ries630/ZaimViewer/issues/39)、[ADR-0017](0017-adr-in-repo.md)、[ADR-0024](0024-dark-mode-follows-device.md)

## 背景

プロジェクト指示は `CLAUDE.md` にあり、Claude Code しか読まない。Codex も使いたいという
動機から見直したが、目的は特定のエージェントへの追従ではなく、ベンダ依存を外すこと。

`AGENTS.md` はリポジトリルートに置くことまで仕様が定まっており、20 以上のツールが
対応している。Claude Code だけがこれを読まず、公式ドキュメントが「Claude Code は
`CLAUDE.md` を読みます。`AGENTS.md` ではありません」と明記したうえで、`CLAUDE.md` から
`@AGENTS.md` でインポートするか symlink を張る回避策を案内している。

このリポジトリ固有の事情が 2 つある。

**スキル定義を持っていない。** `.claude/skills/` が無いので、移行は指示ファイルの層だけで
完結する。スキルの置き場所（`.agents/skills` という慣習が複数ベンダで採用されている一方、
規格は探索ディレクトリを規定していない）は、このリポジトリでは判断する必要がなかった。

**Tailwind の走査対象がファイル名で指定されている。** `src/index.css` の `@source not` が
`CLAUDE.md` を名指ししており（→ [ADR-0024](0024-dark-mode-follows-device.md)）、リネームすると
指示ファイルが走査対象に戻る。実測すると raw 70.65 → 71.19 kB、gzip 12.48 → 12.60 kB で、
**除外し忘れると 0.54 kB（gzip 0.12 kB）が地の文のクラス名として本番 CSS に混入する。**
ADR-0024 が記録した 13 kB 規模の削減は `docs/` を含めた効果で、指示ファイル単体の寄与は
これだけ小さい。問題は量ではなく、**テスト・lint・型検査がすべて通るため検出経路が無い**こと。

## 決定

`CLAUDE.md` を `AGENTS.md` にリネームし、`CLAUDE.md` は `@AGENTS.md` の 1 行だけにする。
あわせて `@source not` の名指しと、規範の正として `CLAUDE.md` を参照していた箇所
（`docs/adr/README.md`、`worker/src/queries.ts`）を差し替える。

## 検討した代替

**`CLAUDE.md` を `AGENTS.md` への symlink にする。** 公式が案内している選択肢で、ファイルが
1 つ減る。落としたのは Claude 固有の記述が必要になったときに置く場所が無くなるためと、
Windows で clone したときに symlink が実体化しないため。インポートなら 1 行足すだけで済む。

**両方に実体を置く。** 複製した時点から二重管理が始まり、片方が必ず古くなる。実際、
移行前に両方が並存した短い期間に、数コミットで内容が食い違い、片方にしか無い記述が
生まれていた。採らない。

**`CLAUDE.md` のまま据え置く。** Codex から同じ指示を読ませられない。移行のコストは
リネームと参照の差し替えだけで、据え置く理由が無い。

## 結果

**`@source not` と指示ファイル名の結合が残る。** 今回は移行にあわせて直したが、この結合
自体は解消していない。次にファイル名を変えるときも同じ漏れが起きうるうえ、CI では
落とせない（サイズが増えるだけでビルドは通る）。

**`CLAUDE.md` が「中身の無いファイル」として残る。** 1 行だけのファイルが増え、
知らずに開いた人は指示がここにあると誤解しうる。

**Claude Code 以外での動作は未確認。** `AGENTS.md` を実際に読ませて確かめたのは
Claude Code 経由のみで、Codex で開いて指示が効くことは検証していない。

## 再評価のサイン

- Claude Code が `AGENTS.md` をネイティブに読むようになった → `CLAUDE.md` を消せる
- スキル定義を持つようになった → 置き場所（`.agents/skills` と `.claude/skills`）の
  判断が新たに必要になる。その時点で各エージェントの探索パスを調べ直して決める
- `@source not` の漏れが再発した → ファイル名で結合するのをやめ、走査対象の指定を
  拡張子やディレクトリ単位に変えることを検討する
