# ADR-0010: ミラー DB に Cloudflare D1 を使う

- ステータス: 承認済み
- 日付: 2026-08-07
- 関連: `11ba2a6`、`bafc466`、[ADR-0004](0004-sqlite-as-mirror.md) を置換

## 背景

[ADR-0009](0009-migrate-to-workers.md) で Cloudflare Workers に移ったため、
ローカルの SQLite ファイルは読めなくなった。DB を Workers から届く場所に置き直す。

判断時点で分かっていた実測値。

| 項目 | 実測 |
|---|---|
| 明細件数 | 4,362（payment 3,266 / income 607 / transfer 489） |
| マスタ | categories 46 / genres 129 / accounts 36 |
| DB サイズ | 3.3MB |
| 読み取り API のクエリ数 | 1 リクエストあたり 2〜3 |
| 全件同期 | 約 17 秒、44 リクエスト、約 4,600 文 |

## 決定

Cloudflare D1 を使う。

## 検討した代替

- **Turso（libSQL）** — 無料枠は D1 より大きい（5GB / 5 億行月）。D1 固有の制限、
  すなわち LIKE / GLOB パターン長 50 バイトと invocation あたりクエリ数の
  どちらも無い。**制限だけを見れば Turso が上**。

  それでも D1 を採るのは、実測でどの制限にも余裕があるため。DB は 3.3MB で
  5GB とは 3 桁違い、読み取りは 2〜3 クエリで上限 50 とは 1 桁違う。
  余裕があるなら、ネイティブバインディング（`env.DB` が最初から生えていて、
  認証トークンも外部への HTTP も要らない）の単純さが勝つ

## 結果

- **キーワード検索が UTF-8 で 48 バイトまでになる。** D1 は LIKE / GLOB の
  パターン長を 50 バイトに制限しており、前後の `%` を引いて 48。日本語なら 16 文字。
  標準の SQLite ビルドは 50,000 なので**ローカルでは踏めず、本番 D1 でのみ失敗する**。
  そのため zod スキーマ側で 48 バイトを検証している
- **同期を Worker 内で完結できない。** invocation あたりのクエリ数制限
  （無料 50 / 有料 1,000）に対し、同期は約 4,600 文。有料プランでも 1 回に収まらない。
  → [ADR-0015](0015-sync-outside-worker.md)
- ファイル差し替えができなくなった → [ADR-0012](0012-table-swap-sync.md)
- 認証トークンも外部通信も不要。Worker 側のコードから見て DB は最初からそこにある

## 再評価のサイン

- **LIKE の 48 バイトが実際に邪魔になったとき。** 日本語 16 文字を超える
  キーワードを打ちたくなる場面が続いたら
- **同期を Worker 内で完結させたくなったとき。** 手元での実行
  （[ADR-0015](0015-sync-outside-worker.md)）が運用として重くなった場合
- 乗り換えは [ADR-0011](0011-driver-agnostic-db-types.md) により
  `drizzle-orm/d1` → `drizzle-orm/libsql` の差し替えで済む見込み
